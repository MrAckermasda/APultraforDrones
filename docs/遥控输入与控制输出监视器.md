# 遥控输入与控制输出监视器

日期：2026-10-27。适用环境：本工作区 Ubuntu / x86_64 / ROS 2 Jazzy / Python 3.12；手柄 USB 接收器插在电脑上。

## 启动窗口

在本机图形桌面的新终端运行：

```bash
cd /home/lyl/ros2_ws
source scripts/setup_pc.bash
ros2 run peripherals gamepad_monitor
```

窗口独立监视输入输出，并提供可选的关节点动参数调节：不启动手柄控制节点、不打开控制板串口、不发布舵机指令、不调用运动服务。只有点击参数按钮时才向目标手柄节点发送参数读取或设置请求。关闭窗口只结束监视和记录，不停止机械臂，也不是急停。

已有的底层驱动、servo_controller、joystick_control 可以保持运行。为了记录初始化姿态指令，可先打开监视器、待话题发现完成，再按原操作指南启动手柄控制节点；该控制节点仍会发送原初始化姿态。不要因为打开监视窗口而重复启动驱动。

仅打开监视窗口就可以观察电脑手柄输入；要观察输出，仍需正常的控制链。控制链启动方式见 [电脑USB手柄控制排障与启动.md](电脑USB手柄控制排障与启动.md)。

## 在窗口里调节 joint_step 与 joint_duration

2026-10-27 新增：窗口上方提供两个输入框、“读取当前值”和“应用两项参数”。目标节点默认 `/joystick_control`。

**升级后需要先结束旧手柄 launch 并重启一次，以加载支持参数热更新的代码，同时重启窗口。** 保留正常运行的底层驱动和 servo_controller，不要启动第二套驱动。手柄节点重启仍会发送原初始化姿态，请先清空活动范围并松开所有按键。之后每次调参均不需要重启节点。

终端 B，结束旧手柄 launch 后：

```bash
cd /home/lyl/ros2_ws
source scripts/setup_pc.bash
ros2 launch peripherals joystick_control.launch.py \
  enable_kinematics:=false joint_step:=5 joint_duration:=0.10
```

另一个桌面终端打开窗口：

```bash
cd /home/lyl/ros2_ws
source scripts/setup_pc.bash
ros2 run peripherals gamepad_monitor
```

1. 点击“读取当前值”。窗口收到节点返回后显示“上次确认”的值及时间；输入框初始的 `5 / 0.10` 只是待应用值，并不证明当前节点使用这些值。
2. 修改 `joint_step`（整数 **1–20 pulse**）和 `joint_duration`（**0.02–30 秒**）。步长不是角度，时间是每条点动指令的运动时间。
3. 松开手柄按键，点击“应用两项参数”。窗口通过 ROS 的原子参数设置服务一次提交两项；任意一项不合法，整个请求被拒绝，原值保留。
4. 等待“节点确认已应用”后，再短按一次手柄观察下一次点动输出。改参数本身不发运动指令，不改变已经发出的运动目标，不触发初始化或 START 回中，也不改变这些固定动作的时间。

步长相同时，增加运动时间通常使这一次点动更慢；时间相同时，减小步长使这一次移动更小。实际效果需结合负载和舵机响应观察，不能把参数比值当作保证的实测速度。

两项参数在服务事务成功提交后才更新控制节点内部缓存，输入回调和参数服务共享互斥回调组，避免输入处理读到一半新值。其他笛卡尔参数仍为只读启动参数，未开放热更新。

成功/拒绝/超时及请求值会进入事件时间线，记录开启时也写入 JSONL/CSV，来源标记为 `settings`。未连接时不会发送请求；旧版本节点会拒绝只读参数，需重启新版节点。请求超时不意味着远端一定没有应用，窗口会提示“当前值未确认”，请读取当前值后判断，不自动重复发送。关闭窗口也不能撤销已经提交的参数请求。

值仅在当前手柄节点进程内生效，不写回 launch、配置文件或固件；下次启动仍采用启动命令的参数。窗口的“上次确认”不是持续推送的参数状态，如果另一个终端改过参数，请重新读取。

若使用了其他节点名或命名空间，显式指定目标，例如：

```bash
ros2 run peripherals gamepad_monitor --control-node /arm1/joystick_control
```

不要运行多个同名手柄节点，避免参数服务目标不明确。

## 窗口内容

| 区域 | 内容 | 如何理解 |
|---|---|---|
| 手柄输入 | B0、B1 等按钮按下/松开，A0、A1 等轴的原始值及归一化值 | 独立读取 Linux `/dev/input/js0`；初始化快照单独标记，不计入新的无线输入事件 |
| 上层目标 | `/servo_controller` 中的舵机 ID、目标位置、单位、指令时间 | 控制程序要求的目标，单位直接取消息字段 |
| 底层指令 | `/ros_robot_controller/bus_servo/set_position` 中的目标 pulse 和时间 | 上层转换/限幅后交给串口驱动的消息；不证明串口已发送成功 |
| 命令缓存 | `/controller_manager/servo_states` 的 position | 本仓库记录的已发目标位置，**不是舵机编码器实测位置** |
| 链路状态 | 每个话题的发布者数、已接收数量、上次接收距今时间 | 发布者为 0 时先检查对应节点或 ROS 环境；发布者存在也不代表正在发命令 |
| 事件时间线 | 本机接收时间、来源、输入或输出内容 | 最多显示最近 500 条；自动记录的文件保留本窗口记录期间收到的事件 |

输入按钮使用 Linux 原始编号，不猜测不同设备的“方块/圆圈”等名称。Linux 轴编号也不等于 pygame 的轴/hat 编号，十字键可能表现为两个轴变化。界面归一化值为 -1 到 +1，进度条左端 -1、中间 0、右端 +1；原始值仍保留。

这里没有订阅 `/joy`：现有 `joystick_control` 直接用 pygame 读取设备。窗口独立只读打开 Linux 手柄设备，不独占设备，不修改按键映射；只有用户点击“应用两项参数”时才请求更新点动步长与指令时间。原始输入出现在窗口中，只证明电脑收到了输入，不能保证控制节点接受了这次输入。

上层、底层话题都可能有其他程序发布；窗口不会把它们强行归因于某一次手柄按键。ROS 消息没有逐次按键关联 ID，多个来源的回调顺序也不是端到端的严格执行顺序，所以只能对照接收时间排障，不能据此精确测量控制延迟。表格保留最近收到的值，旧值不会因为节点断开自动变成零；结合上方接收时间判断是否新鲜。

## 记录文件与操作按钮

默认打开窗口即开始记录，保存目录为：

```text
$ARMPI_WS/log/gamepad_monitor/
```

正常加载本工作区环境后即 `/home/lyl/ros2_ws/log/gamepad_monitor/`。未设置 `ARMPI_WS` 时使用用户主目录下的 `log/gamepad_monitor`。

每次记录创建一对同名文件：

- `gamepad_日期_时间_微秒.jsonl`：每行一个 JSON 事件，可用 Python 分析。
- `gamepad_日期_时间_微秒.csv`：UTF-8 BOM 编码，便于表格软件打开。列为 `seq,time,elapsed_s,source,kind,data_json`；多舵机目标放在 `data_json` 中，不会只保留最后一个舵机。

事件带本机接收墙钟时间（含时区）、窗口启动后的单调时钟秒数、来源和数据。手柄数据额外保留设备时间戳、初始化标志、原始值。每条记录刷新到文件；磁盘空间不足或目录不可写时，窗口会明确显示“记录失败”，监视继续。窗口不是硬实时抓包工具，设备或 ROS 队列在高负载下可能丢失事件，不承诺捕获启动之前或断开期间的消息。

| 按钮 | 行为 |
|---|---|
| 停止记录 | 关闭当前文件，实时监视继续 |
| 开始新记录 | 创建新文件，不覆盖上次记录 |
| 暂停事件列表 | 暂停列表追加；输入指示、舵机表格、文件记录继续；恢复后不补放暂停期间的列表 |
| 清空事件列表 | 只清空屏幕列表，不删除文件，也不清除舵机最近值 |
| 列表显示命令缓存 | 默认关闭以避免状态话题刷屏；记录开启时，缓存消息仍写入文件 |

指定设备及记录目录：

```bash
ros2 run peripherals gamepad_monitor \
  --device /dev/input/js0 \
  --log-dir "$HOME/armpi-recordings"
```

也可以先只监视，之后在窗口点击开始记录：

```bash
ros2 run peripherals gamepad_monitor --no-record
```

多手柄时请明确选择实际接收器对应的 `/dev/input/jsN`。自动重连会重试同一路径；拔插后设备编号改变时，需要重启并指定新路径。没有输入权限或设备缺失会显示在窗口中，重试间隔约 1 秒。

## 排障顺序

1. 手柄按一下、松开，查看“非初始化事件”是否增加。只有初始化快照不能证明无线配对正常。接收器留在控制板上时，本窗口无法从电脑 Linux 输入设备读到它。
2. 输入有变化，上层目标无消息：看 joystick_control 是否运行、是否在等待控制器、是否已有舵机状态，以及该按钮是否有映射。现有程序不会把所有模拟轴输入都转换成动作。
3. 上层有消息，底层无消息：检查 servo_controller 和底层驱动是否就绪、消息单位及控制器日志。
4. 底层有消息，机械臂不动：窗口不能证明串口通信或硬件执行正常，应继续检查驱动日志、供电与实际通信。

窗口的终端应与控制节点加载相同的 ROS 工作区和 `ROS_DOMAIN_ID`，网络发现设置也需一致。默认监视绝对话题名；如部署改用了其他命名空间，可用 ROS 标准 remap 参数，例如：

```bash
ros2 run peripherals gamepad_monitor --ros-args \
  -r /servo_controller:=/arm1/servo_controller \
  -r /ros_robot_controller/bus_servo/set_position:=/arm1/ros_robot_controller/bus_servo/set_position \
  -r /controller_manager/servo_states:=/arm1/controller_manager/servo_states
```

如果提示缺少 Tk，先执行 `sudo apt install python3-tk`。本机已确认 Tk 8.6 可用，无需安装。纯 SSH 且没有图形显示时无法打开窗口，应在本机桌面终端运行。
