# 20261028-4573每周工作汇报-刘英伦

汇报周期：2026年10月26日—11月1日（本稿截至10月28日）

## 一、本周进展与收获

### （一）学习科研进展与收获

**· 深化机械臂运动学建模与正逆解的工程理解**

本周我在前期旋量理论与机器人运动学学习的基础上，结合ArmPi Ultra机械臂的实际结构和控制程序，进一步梳理了Modified DH建模方法、关节坐标系、基座高度、末端工具偏置以及舵机脉宽与关节角度之间的映射关系。明确了该机械臂用于末端定位的关节为五个，夹爪开合不属于独立的位姿自由度，因此求解目标应结合机械结构约束，不能将六个舵机直接等同于可任意控制六维位姿。

通过核对厂家教程中的逐节变换矩阵和几何法逆解，我进一步理解了底座旋转、平面连杆求解、多解选择、关节限位及奇异姿态的处理方法。同时发现教程中部分简化条件和最终旋转矩阵不能直接作为通用计算公式，因而采用逐节矩阵连乘，并通过独立几何展开及数值回代进行验证。这一过程加深了我对“数学模型内部一致”和“模型符合实际机械结构”两类验证的认识，为后续无人机与机械臂协同控制打下基础。

**· 梳理运动学库的实现方式与跨平台兼容问题**

针对原厂运动学库无法在当前电脑加载的问题，我检查了二进制文件的架构、符号和调试信息，确认其为面向ARM aarch64平台的Cython扩展，并带有Python 3.10构建环境的线索。随后核查原始ROS2资料包、STM32工程及高级控制教程，发现当前交付资料中未包含对应的完整算法源码；STM32侧同样以接口头文件和编译库提供核心运动学能力。此外，对比了专用解析求解与KDL数值求解的适用方式，明确后续引入KDL时仍需统一关节零位、坐标系及任务约束，目前尚未切换算法后端。

### （二）项目进展与收获

**· 推进机械臂ROS 2程序向电脑平台迁移**

本周我围绕后续机载部署需求，在Ubuntu 24.04、ROS 2 Jazzy和Python 3.12环境下整理并适配了机械臂工作区。将原程序中依赖固定用户名和目录的资源路径改为可配置或相对工作区定位，统一串口、波特率、动作组及外设配置入口，并完成相关ROS包构建与兼容性检查。同时修复舵机读取超时及失败状态处理问题，为后续通信排障和跨设备部署建立了统一入口。

**· 完善电脑端手柄控制与调试工具**

针对电脑USB手柄控制链中的问题，修复了输入回调阻塞、pygame接口使用及无运动学后端时的关节模式接入问题，增加关节点动步长与运动时间参数。在此基础上开发遥控输入与控制输出监视窗口，支持观察手柄输入、上层目标、底层指令和指令位置缓存，并通过参数服务调整点动参数。特别区分了“已发送的目标位置”和“实际测得的舵机位置”，避免将控制缓存误判为机械臂已到位；相关功能已完成软件和模拟接口验证。

**· 实现可部署的Python FK/IK后端**

为降低对原厂平台专用库的依赖，我依据已核对的几何参数实现了Python正运动学、解析逆运动学及脉宽转换，并补充多解选择、不可达目标拒绝、关节边界和整数脉宽量化后的误差检查。随后将其封装为独立ROS 2服务后端，支持标定参数配置和真实总线位置读取，在反馈缺失或过期时拒绝输出运动学目标。验证覆盖400组随机关节姿态的FK→IK→FK回代、完整旋转一致性，以及服务请求与反馈异常处理。

**· 补齐实机小步验证流程与工程记录**

在实物几何条件已核对的基础上，新增小范围笛卡尔位移验证工具，形成“实测位置读取—轨迹预览—分段执行—回读检查—结果记录”的流程。工具默认只预览，显式执行时限制相对位移不超过5 mm，并检查关节偏移、轨迹连续性和其他控制程序的命令冲突；异常或中断时尝试发送停止请求。当前完整自动化测试达到255项通过，相关ROS包构建成功，分段执行和中断处理已通过模拟控制板验证。

同时整理了迁移记录、手柄排障、运动学部署、源码定位和实机操作文档，并完成本地版本管理及Git代理配置。当前成果主要完成了软件实现、构建和模拟验证，尚未取得独立实测的末端定位精度或真实运动验收结果，也尚未完成Jetson Orin NX部署。考虑到下一阶段目标平台已明确，我暂缓进一步调整算法后端，优先保留可复现的代码与配置，待目标设备环境确认后统一推进。
